# 埋め込みモデルと検索方式の比較 (設計メモ 5.5 / 5.7, 手順 6)

論文の検索 (title + abstract) について, 埋め込みモデル, 文書側の入力, 検索方式を評価データで比べた (2026-11-27〜28).

## 結論

- **Qwen3-Embedding-0.6B を採用し, 文書の入力は title + abstract (カテゴリは付けない) とする.**
  - 検索方式は hybrid-lang にする. 英語の質問は BM25 と kNN を RRF でまとめ, 日本語の質問は kNN だけを使う.
- **BGE-M3 より Qwen3-0.6B がやや良い.** 引用の文脈では R@10 が +3.8 点 (95% 区間 +0.0〜+7.4) だった. 日本語ではほぼ同じだった.
- **カテゴリを付けても良くならない.** R@10 は -1.6 点で, 有意な差はなかった.
- **hybrid は英語の質問で効く.** 引用の文脈では kNN だけより R@10 が +3.8 点 (95% 区間 +0.2〜+7.2) だった.
  - 日本語の質問を hybrid にすると BM25 が雑音になり, MRR が 0.83 から 0.41 に落ちる. このため日本語は kNN だけにする.
- **Qwen3-4B は明らかに良い.** 引用の文脈では R@10 が +11.2 点 (95% 区間 +7.8〜+14.6), MRR が +12.6 点で, 日本語では R@10 が 100% だった. それでも初期には採らない. 理由:
  - 質問のベクトル化は search1 の CPU (i5-1135G7) で p95 300ms 以下が目標だが, 4B は 0.6B の約 7 倍の計算になる.
  - ベクトルが 2560 次元になる. fp16 の 314 万件で約 16GB あり, 1024 次元なら約 6.4GB で済む.
  - 全件のベクトル化は DGX Spark 2 台で約 27 時間かかる. 0.6B なら約 7.4 時間.
  - 4B は手順 4 で search1 の遅延を測った後に再検討する. その場合は MRL で 1024 次元に切り詰めた場合も評価する.
  - `paper_embeddings` にモデルと版を記録するため, 後から入れ替えられる.
- 4B は 4B 自身でも hybrid にすると悪くなる (MRR -6.7 点). 埋め込みが十分強いと, BM25 は順位を乱すだけになる.

## 注意

- **文書集合が全件より小さい.** 150,560 件で, 全件は 314 万件. 全件では数値が下がる. 比べているのは条件の間の差である.
  - 文書集合に入れた正解は, 引用の文脈の正解 1,499 件と要旨の質問の論文.
- **引用の文脈の正解は引用先 1 件だけ.** 他に関係のある論文を上位に出しても外れとして数えるため, 値は低めに出る.
  - 引用文の中には, 引用先を特定できない一般的な文も残っている. 例: 「[cite] の手法を使った」.
- **要旨からの質問は Claude が書いた.** 実際の利用者の質問より語が要旨に近い.
  - 手作りの質問 (50〜100 件) はまだない. 利用者が作る必要がある (下記).
- 質問側の指示文は Qwen3 だけに付けた: `Instruct: Given a research question, retrieve relevant arXiv papers\nQuery: `. BGE-M3 には指示文を付けていない.
- kNN は全件の厳密な内積で求めた. OpenSearch の HNSW (fp16) の近似による低下は含まない.

## 評価データの作り方

出力は RustFS の `s3://arxiv-raw/eval/v1/` に置いた.

| ファイル | 内容 |
|---|---|
| `queries.parquet` | 708 件 |
| `corpus.parquet` | 328,764 件 |
| `cite_kept.parquet` | 引用の文脈の候補 1,780 件 |
| `emb/` | 文書のベクトル |
| `results/<run>/` | 結果の JSON. 質問ごとの順位も入っている |

スクリプトは `data/` にある.

1. **引用元を取る**: `fetch_citing.py citing.parquet <lo>:<hi> ...`
   - 2023〜2026 年の狭い paper_id の範囲を指定し, paper_text と metadata を取る. 3,317 論文.
   - 環境変数 `TRINO_PASSWORD` が要る.
2. **引用の文脈を抜き出す**: `cite_ctx.py citing.parquet cite_raw.parquet`
   - 参考文献 (`\bibitem` / biblatex の `\entry`) のうち, arXiv ID が書かれているものを対応表にする.
   - 本文の文のうち, そのキーを 1 つだけ引用している文を texnorm で正規化し, 質問にする. 正解は引用先.
   - 12〜60 語で, `$` が 4 個以下の文だけを残す. 6,221 件.
3. **絞り込む**: `cite_filter.py cite_raw.parquet cite_kept.parquet`
   - 「see Ref.」や図・式・節の参照, 「et al.」を含む文を除く. 4,582 件.
   - 1 論文から最大 2 件にする. 1,780 件.
   - 主カテゴリで 13 層に分ける.
4. **文書集合を作る**: `fetch_corpus.py cite_kept.parquet corpus.parquet`
   - metadata の 10% (paper_id の xxhash64 で選ぶため再現できる) と引用先の論文を合わせる.
   - 引用先 1,501 件のうち 1,499 件が metadata にあった.
5. **要旨の質問を作る論文を選ぶ**: `pick_llm_papers.py corpus.parquet cite_kept.parquet llm_papers.json`
   - 13 層から 8 件ずつ選ぶ. 選んだ要旨を読んで, 英語と日本語の質問を `llm_questions.json` に書く (今回は Claude が書いた).
6. **質問をまとめる**: `make_queries.py cite_kept.parquet corpus.parquet llm_questions.json llm_papers.json queries.parquet [manual_questions.json]`
   - 引用の文脈から, 13 層でほぼ均等に 500 件を選ぶ (種 42).
   - 同じ入力からは同じ出力になることを確かめた.

`llm_papers.json` は要旨を含むため, リポジトリには置かず RustFS に置いた.

### 手作りの質問を足す

1. `data/manual_questions.template.json` を参考に, `manual_questions.json` を書く. 中身は「実際に探したい論文の質問」と「正解だと思う論文 (複数可)」の組で, 50〜100 件が目安.
2. 正解の論文を文書集合に入れる. 手順 4 の `fetch_corpus.py` に正解を追加して作り直す.
3. `make_queries.py` に 6 番目の引数として `manual_questions.json` を渡して作り直す.
4. 再評価する (下記).
   - 結果には `manual` の行が加わる. 正解が複数ある場合は, 最も上の正解の順位で数える.
   - 文書集合を変えたら, 保存したベクトル (`emb/*.npy`) を消してから実行する.

## 実行

```sh
kubectl apply -k deploy/science-systems/embedding-eval     # DGX Spark の GPU を 2 つとも使う
kubectl -n science-systems logs -f -l app=embedding-eval --prefix
kubectl delete -k deploy/science-systems/embedding-eval    # 終わったら
```

- index 0 は Qwen3-0.6B (カテゴリの有無) と BGE-M3 で, 約 1 時間 45 分かかる. index 1 は Qwen3-4B で, 約 2 時間 40 分かかる.
- 実行中は GPU Workspace, Trainer, ローカル LLM を使えない.
- 文書のベクトルは `emb/` に保存し, 次回は再利用する. 再利用する場合, BM25 と検索だけなので数分で終わる.
- モデルの版は固定している:

  | モデル | 版 |
  |---|---|
  | Qwen3-Embedding-0.6B | `97b0c614` |
  | Qwen3-Embedding-4B | `5cf2132a` |
  | BGE-M3 | `5617a9f6` |

- 依存は起動時に `pip install --user` で入れる. `--target` を使うと pip がイメージの torch を入れ直そうとする.
